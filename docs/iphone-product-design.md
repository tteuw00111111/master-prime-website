# iPhone configurator — design and validation

North star: **see the phone, compare actual prices, choose a configuration, and continue the quote without losing context.** The chosen direction keeps Master Prime’s black/gold identity and Britanica fonts, with Apple-inspired product prominence. This is a web quote form, so native app navigation conventions do not apply.

## Final presentation

- The orange 3D phone is the default presentation, following the user’s later preference. A complete orange Apple Store Pro Max composition remains visible until 3D is ready. Neither preview selects a commercial color. Capacity precedes color in both DOM and visual order.
- Desktop pairs a stable 500px gallery with configuration; mobile uses a 240px stage and compact header/progress. Capacity is visible above the action bar at 390×844.
- Overview and camera detail are deliberate static views. The old overlapping lineup and CSS rear crop are removed.
- Decoded images dissolve over 420ms with eased acceleration and deceleration; switching between overview and camera detail adds a subtle 2.5% settling zoom anchored to the handset. The prior image remains during loading and through the complete fade. Errors and retry belong to the individual image. Reduced motion disables fades, zoom and press scaling.
- The five-step qualification keeps its existing prices, payment confirmation, purchase timing, trade branches, draft, review edits, attribution and WhatsApp intent semantics. Payment choices display their applicable amounts.
- One persistent action element stays outside the 180ms step fade. The existing viewport hook observes its height, reserves space at page end, and hides it while the on-screen keyboard is open. Focused controls use matching scroll margins. Step navigation focuses the heading.
- Supporting prices are at least 14px; form text is 16px; gallery controls are at least 44px and configuration controls at least 48px. Color selection has a ring, text and pressed state. Supporting links and business details remain reachable.
- UI labels consistently use “Prateado” and “Escolha a cor”. The catalog and WhatsApp message retain original commercial naming. The final WhatsApp action retains the shared site’s existing green destination treatment; normal actions and selection remain gold.

## Default 3D with a photo fallback

The viewer dynamically imports `@google/model-viewer` after hydration at browser idle (with a short timeout fallback), and then loads the 2.76MB model. This intentionally replaces the earlier opt-in/no-initial-download requirement at the user’s request. Photos and configuration work independently of 3D; the form never waits for model loading. To support lower-end phones, Data Saver, reported connections at 3G or slower, reported memory at or below 2GB, and two or fewer CPU threads start with photos and make no automatic 3D download. These browser hints are not universally available; unknown devices use default 3D with the normal GPU fallback. Manual activation remains available. The existing viewer uses adaptive resolution and stops drawing when idle; textures are capped at 1024px. “Voltar às fotos” switches to static views; “Explorar em 3D” returns to the model.

The viewer keeps a poster until loading succeeds, supports bounded zoom and rotation, preserves camera position when the finish changes, and offers Frente / Traseira / Câmeras / Voltar às fotos. Vertical touch gestures scroll the page (`pan-y`). There is no automatic rotation, AR, or scroll-driven camera. Leaving and returning to the product step restores the default 3D presentation with the selected finish, reusing the cached model.

WebGL2 availability is checked before creating the viewer. Missing GPU support, model errors and loading timeout retain the poster and a photo fallback. A failed model never blocks qualification. Runtime import errors also show fallback.

The source is the user-supplied `/home/wayne/Downloads/17_pro_max_laranja/apple-iphone-17-pro-max/` folder. Static files and their original source URLs/hashes are recorded in `src/assets/images/iphone/apple-17-pro-max/sources.json`. Shared Pro detail imagery and Pro geometry were explicitly authorized for this Pro Max presentation. They are product illustrations, not store-unit photos or proof of stock/condition. The 18 Pro Max uses its own supplied renders and 3D asset as described below. Seminovos now use the reference galleries described below; photos of an actual unit remain part of the WhatsApp consultation.

`node scripts/prepare-iphone-model.mjs /path/to/3d/web-viewer` produces `src/assets/models/iphone/iphone-17-pro.glb`. It translates Apple’s color-state definitions into orange/blue/silver glTF material variants, applies the source upright orientation and metre scale, preserves specified UV channels, converts textures to WebP and deduplicates geometry. The model is 2.76MB, below the 5MB limit enforced by the script. `sources.json` records every input hash, output hash and conversion details. Standard PBR lighting replaces Apple’s proprietary Lotus shading, so this is not a pixel-identical reproduction of Apple’s renderer.

## Independent visual review

One isolated reviewer inspected the mobile/desktop product, 3D and review screenshots against the existing-interface oil-ui rubric (no score). Findings and responses:

- 3D blur: early screenshots caught the adaptive renderer before its final full-resolution frame. Settled captures are now taken after camera and render updates, and the source screen texture was inspected directly. Keep adaptive resolution for responsive interaction; do not force maximum GPU use on phones. Material differences from Apple’s custom renderer remain a known limit.
- Silver naming and inconsistent color prompt: normalized the UI labels; original catalog/message values are preserved.
- Excess space before privacy/breadcrumbs: removed duplicate form-bottom action-bar reservation; the page still reserves measured action space.
- Green WhatsApp action: retained because it is the existing shared destination convention used before this refinement.
- Preserve capacity-first ordering, visible cash/installment comparisons, strong initial product imagery, and the photo fallback. After this review, the user explicitly chose 3D as the default. No additional content deletion was warranted.

The reviewer evaluated screenshots, not animation or interaction. The final adaptive/default-3D behavior was added following the user’s later preference and verified by the primary agent. Browser automation separately checks behavior. The host Playwright fallback was used; no oil-ui screenshot-tool lint report was produced. No new visual direction, generated product image, unrelated redesign, production deployment or messaging was introduced.
